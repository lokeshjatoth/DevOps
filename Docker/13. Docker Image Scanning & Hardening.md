Key Concepts
- Vulnerability Scanning: The process of analyzing a Docker image to identify known security vulnerabilities in its OS packages and application dependencies (e.g., npm, pip, Maven packages). Tools like Trivy compare the image contents against CVE databases.

- CVE (Common Vulnerabilities and Exposures): Publicly disclosed security flaws. Scanners map packages and versions to known CVEs to produce findings with severities and (if available) fixed versions.

- Attack Surface: The total set of exposed components that could be attacked. Using smaller, up-to-date base images and removing unused tools helps reduce this surface.

- Hardening: Securing an image by minimizing packages, running as a non-root user, avoiding debugging tools in production, and keeping the base image current. Multi-stage builds help keep the final image lean by excluding build tools.



1. Pull an older, intentionally vulnerable image: `python:3.8-slim-buster`.
```
sudo docker pull python:3.8-slim-buster
```

2. Scan the old image with Trivy (containerized) to see all vulnerabilities.
```
sudo docker run --rm -v /var/run/docker.sock:/var/run/docker.sock aquasec/trivy:latest image python:3.8-slim-buster
```

3. Pull a newer Python base image (Bookworm or later) to compare: `python:3.11-slim-bookworm`.
```
sudo docker pull python:3.11-slim-bookworm
```

4. Scan the newer image with Trivy and compare results to the older image.
```
sudo docker run --rm -v /var/run/docker.sock:/var/run/docker.sock aquasec/trivy:latest image python:3.11-slim-bookworm
```

5. Create a Dockerfile with an unnecessary tool and an old base image. This will introduce vulnerabilities.
```
cat <<EOF > Dockerfile.bad
FROM alpine:3.17
RUN apk add --no-cache curl=7.88.1-r1
CMD ["echo", "Ready."]
EOF
```

6. Build this less secure image and tag it `insecure-app`.
```
sudo docker build -t insecure-app -f Dockerfile.bad .
```

7. Scan `insecure-app` with Trivy to observe the vulnerabilities.
```
sudo docker run --rm -v /var/run/docker.sock:/var/run/docker.sock aquasec/trivy:latest image insecure-app
```

8. Create a hardened Dockerfile: use the latest base image, run as a non-root user, and install no extra tools.
```
cat <<EOF > Dockerfile.good
FROM alpine:latest
# Create non-root user and group
RUN addgroup -S app && adduser -S app -G app
USER app
# Minimal runtime command
CMD ["echo", "Hardened and minimal."]
EOF
```

9. Build the hardened image and tag it `secure-app`.
```
sudo docker build -t secure-app -f Dockerfile.good .
```

10. Scan `secure-app` with Trivy and compare results to `insecure-app`. It should be clean.
```
sudo docker run --rm -v /var/run/docker.sock:/var/run/docker.sock aquasec/trivy:latest image secure-app
```

11. Bonus: Generate a machine-readable JSON report for `insecure-app` to see how this could be used in a CI pipeline. Saved locally as `trivy-insecure.json`.
```
sudo docker run --rm -v /var/run/docker.sock:/var/run/docker.sock -v "$PWD":/work aquasec/trivy:latest image -f json -o /work/trivy-insecure.json insecure-app
```
